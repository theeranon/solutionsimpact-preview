Performance — จุดที่เพิ่มความเร็วได้

วิเคราะห์จาก scripts + HTML source ที่ load บน homepage จริง

🔴 ไม่มี Page Caching เลย
Critical
ตรวจ HTTP headers และ HTML source ไม่พบ caching plugin (WP Rocket, LiteSpeed Cache, W3TC) ทุก request กระทบ PHP + DB โดยตรง บน shared hosting = ช้ามากเมื่อ traffic สูง
แนะนำ: ติดตั้ง LiteSpeed Cache (ฟรี, server นี้น่าจะเป็น LiteSpeed) หรือ WP Rocket (paid แต่คุ้มมาก) จะเร็วขึ้น 3–10x ในทันที
🔴 JS 15 ไฟล์ โหลดโดยไม่มี defer/async
Critical
จาก source พบ script 17 ไฟล์รวม — มีแค่ 2 ไฟล์ที่ defer/async ที่เหลืออีก 15 ไฟล์ block การ render หน้าเว็บทันที jQuery, Bricks, Swiper, Splide, JetPopup, FluentForm ทั้งหมด load synchronous
Bricks มี settings "Load scripts deferred" ใน Bricks → Settings → Performance — เปิดได้เลย แต่ต้องทดสอบว่า popup/form ยังทำงานปกติ
🟡 FluentForm JS โหลดทุกหน้า
Medium
fluentform-advanced.js + form-submission.js โหลดทุก page request ทั้งที่ form มีเฉพาะบางหน้า เป็น 2 requests รวมกันประมาณ 50KB+ ที่ users ส่วนใหญ่ไม่ต้องการ
ใน FluentForm → Global Settings → Misc → เปิด "Load form script only on pages with forms"
🟡 JetPopup + anime.js โหลดทุกหน้า
Medium
jet-popup-frontend.js + anime.min.js โหลดทุก page ทั้งที่ popup อาจมีแค่ homepage หรือบางหน้า anime.js เป็น animation library ที่หนักพอสมควร
JetPopup → Settings → Advanced → Load scripts on pages where popups exist only
🟡 Slider 2 Library พร้อมกัน: Swiper + Splide
Medium
swiper.min.js และ splide.min.js โหลดพร้อมกันทุกหน้า ทั้งสองเป็น full-featured slider libraries ที่ overlap กันมาก (~150KB รวมกัน) Bricks ใช้ Splide เป็น default ส่วน Swiper อาจมาจาก BricksExtras หรือ JetEngine
ตรวจว่า component ไหนใช้ library ไหน ถ้า standardize ได้เป็น Splide อย่างเดียว Bricks รองรับ Swiper ก็ disable Swiper ออกได้
🟡 Hero image เป็น 2560px screenshot (2x)
Medium
พบ image URL: CleanShot-2026-04-09-at-09.12.21@2x-scaled.png — screenshot จาก CleanShot @2x บน Retina = ไฟล์ใหญ่มาก แม้ EWWW จะ optimize แล้วก็ตาม source file @2x มักใหญ่เกินจำเป็นสำหรับ web
Export image ใหม่เป็น WebP ที่ max 1440px wide แทน ใช้ EWWW convert เป็น WebP อัตโนมัติถ้ายังไม่ได้เปิด
🟢 Google Fonts มี preconnect แล้ว
OK
พบ <link rel="preconnect" href="https://fonts.gstatic.com/"> ใน head — ถูกต้องแล้ว แต่สังเกตว่ามีซ้ำ 2 ครั้ง (ลบ duplicate ได้)
🟢 EWWW Image Optimizer ติดตั้งแล้ว
OK
lazysizes.min.js โหลดอยู่ = lazy loading active, EWWW optimize images อัตโนมัติ ตรวจว่าเปิด WebP conversion ใน EWWW settings แล้วหรือยัง

Positioning — Transformation Consulting ไม่ใช่ Training House

วิเคราะห์จาก H1/H2, meta, navigation structure, schema markup

ปัจจุบัน signal จาก website บอกว่า "สถาบันอบรม" ชัดเจน ทั้งที่ copy ใน hero พยายาม push ว่า "Transformation" แต่ structure โดยรวมยังล้มการ positioning นั้นอยู่ นี่คือจุดที่ conflict:

Navigation — โครงสร้างเมนู
❌ ปัจจุบัน: "Inhouse Training" / "AI-Driven Training" / "Public Course" — ทุก menu item เป็น "Training" หมดเลย
✅ ควรเป็น: มี menu item "Consulting" หรือ "Advisory" หรือ "Business Transformation" แยกออกมา — training เป็น delivery vehicle ไม่ใช่ตัวตนหลักของบริษัท
ตัวอย่าง positioning ที่ดี: McKinsey ไม่ได้บอกว่า "เราสอน Strategy" แต่บอกว่า "เราช่วยให้ธุรกิจ grow" → courses เป็น how ไม่ใช่ what
Nav CTA Button
❌ ปัจจุบัน: "Download คอร์สอบรมองค์กร 2026" — CTA หลักของทั้งเว็บคือ catalog download = สถาบันอบรม 100%
✅ ควรเป็น: "ขอคำปรึกษาฟรี" หรือ "ปรึกษากลยุทธ์" — นำด้วย consulting access ก่อน ส่วน catalog ย้ายไปเป็น secondary CTA
H1 — Hero Headline
❌ ปัจจุบัน: "อัพเกรดทีมของคุณในปี 2026 ให้มีทักษะสำคัญแห่งอนาคต ที่ทุกคนทำงานเก่งขึ้น 10 เท่า"
✅ ดีกว่าถ้า lead ด้วย business outcome ก่อน เช่น "ธุรกิจที่ปรับตัวด้วย AI ได้เร็วกว่าคู่แข่ง — ไม่ใช่แค่ทีมที่ฉลาดขึ้น แต่องค์กรที่ทำงานต่างออกไปทั้งระบบ"
Subheadline ตอนนี้ดีกว่า H1: "หน้าที่ของเราคือการสร้าง Transformation ที่มากกว่าเทรนนิ่งทั่วไป" — อันนี้ควรขึ้นมาเป็น H1
Meta Description + og:title (SEO)
❌ ปัจจุบัน: "SOLUTIONS IMPACT พัฒนาศักยภาพแก่องค์กรเพื่อการเติบโตในธุรกิจ" + "ปลดล็อกศักยภาพขององค์กร ด้วยเครื่องมือที่ล้ำสมัย!" — ฟังดู generic HR vendor
✅ ควรเป็น: บอก specific transformation outcome เช่น "SolutionsIMPACT ช่วยองค์กรนำ AI เข้าสู่การทำงานจริง — ไม่ใช่แค่อบรม แต่เปลี่ยน DNA วิธีทำงานทั้งทีม"
Schema Markup
❌ ปัจจุบัน: Schema type = "Article" ทุกหน้ารวมถึง homepage — Article schema สำหรับ consulting firm = ผิดทั้งหมด
✅ ควรเป็น: Organization + ProfessionalService schema บน homepage, Course schema ในหน้า course จริงๆ สามารถ config ได้ใน Rank Math → Schema → เปลี่ยน default type
หน้าที่ขาด — Missing Pages
❌ ปัจจุบัน: /about/ → 404, ไม่มีหน้า Case Studies, ไม่มีหน้า Our Approach/Methodology, ไม่มีหน้า "Consulting Services" ที่แยกจาก Training
✅ สิ่งที่ consulting firm ควรมี: (1) About/Who We Are — story ของบริษัท ไม่ใช่ list of services (2) Our Approach — methodology ว่า transformation คืออะไรในมุมของ SI (3) Case Studies/Results — proof of work (4) Consulting/Advisory page แยกจาก training catalog
Blog ที่กำลังทำใหม่ (si-blog-redesign) เป็น move ที่ถูกต้องมากในมุม positioning — thought leadership content สร้าง credibility consulting ได้ดีกว่า course catalog ทำได้เพียบ
H2 Structure — Homepage Content Architecture
❌ ปัจจุบัน: H2 ที่ 1 = "เน้นยุค AI x HUMAN โดยเฉพาะ" → H2 ที่ 2 = "หลักสูตร Signature" → H2 ที่ 3 = "หลักสูตรยอดนิยม" — เร็วมากที่จะกลายเป็น course catalog
✅ ควร insert "Why SolutionsIMPACT" section ก่อน course listing — บอกว่า transformation ที่แท้จริงต้องการ partner ที่เข้าใจ business ไม่ใช่แค่ trainer ที่สอนดี จากนั้น courses จะกลายเป็น evidence ของ approach แทน
สิ่งที่ทำได้เพิ่มใน si-blog-redesign (ขยาย scope)
✅ Custom Post Type: Insight/Case Study — สร้าง CPT แยกจาก blog post สำหรับ "ผลลัพธ์ที่เกิดขึ้นจริงกับลูกค้า" เชื่อมกับ industry/service area

✅ Author Profile Page — แสดง expertise ของ consultant/trainer แต่ละคน สร้าง credibility individual-level

✅ Topic Cluster Pages — เช่น /ai-transformation/, /leadership-development/ ที่ aggregate blog + courses + case studies ในหัวข้อเดียว = SEO + positioning ในคราวเดียวกัน

Quick Wins — ทำได้ทันที ผลชัด

  • ลบ user-switching + seo-engine ทันที — security risk + SEO conflict ไม่มีอะไรเสียเลย
  • ติดตั้ง LiteSpeed Cache — เร็วขึ้น 3–10x ฟรี ทำได้ใน 15 นาที
  • เปิด "Load forms only on form pages" ใน FluentForm → ลด JS load ทุกหน้าที่ไม่มี form
  • เปลี่ยน Nav CTA จาก "Download คอร์สอบรม" → "ขอคำปรึกษา" — signal เดียวที่เปลี่ยน perception ได้เร็วที่สุด
  • แก้ Schema ใน Rank Math จาก Article → Organization + ProfessionalService — ไม่ต้องแตะ code เลย
  • เปิด EWWW WebP conversion — images เล็กลง 30–50% อัตโนมัติ
